<task type="auto">
  <name>Task 1: Create ColorTheme model and make GameConfig theme-aware</name>
  <files>lib/game/models/color_theme.dart, lib/game/config/game_config.dart</files>
  <action>
Create ColorTheme class in lib/game/models/color_theme.dart:
- Fields: id (String), name (String), xpCost (int)
- Color fields: backgroundColor, playerColor, obstacleColor, obstacleOutlineColor, obstacleHighlightColor, accentColor, gridColor, pulseColor
- Non-themed colors stay fixed in GameConfig: textColor (white), highScoreColor (gold), dangerTintColor (red — universal danger signal)

Define 5 themes as static instances on a ColorThemes class:
1. **neonRed** (id: 'neon_red', xpCost: 0): Current colors exactly as they are now — backgroundColor 0xFF1A1A2E, playerColor 0xFFE94560, etc. This is the default.
2. **neonBlue** (id: 'neon_blue', xpCost: 750): Deep dark blue bg, cyan/electric blue player, teal obstacles
3. **neonGreen** (id: 'neon_green', xpCost: 2000): Dark green-black bg, lime/neon green player, dark green obstacles
4. **neonPurple** (id: 'neon_purple', xpCost: 4000): Deep purple bg, bright magenta/violet player, indigo obstacles
5. **monochrome** (id: 'monochrome', xpCost: 6000): Pure black bg, white player, gray obstacles — clean minimal aesthetic

Add static `all` list and `getById(String id)` method (with neonRed as fallback).

Refactor GameConfig color fields:
- Add `static ColorTheme activeTheme = ColorThemes.neonRed;`
- Change the 8 themed color `static const Color` fields to `static Color get` getters that delegate to `activeTheme`. For example: `static Color get playerColor => activeTheme.playerColor;`
- Keep non-themed colors as `static const`: textColor, highScoreColor, dangerTintColor, xpDisplayColor

This approach means ALL existing code that uses `GameConfig.playerColor` etc. continues to work unchanged — they just now read from the active theme instead of a constant.

<task type="auto">
  <name>Task 2: Wire theme into rendering components + persist selection</name>
  <files>lib/game/components/player.dart, lib/game/components/obstacle.dart, lib/game/components/background.dart, lib/game/components/background_pulse.dart, lib/game/pulse_game.dart</files>
  <action>
Components that cache color in constructors or static fields need refresh logic when theme changes. Theme changes only happen between games (from the gallery screen, not during gameplay), so we need a "refresh colors" pass.

1. **Player**: Already has resetVisuals() which sets `paint.color = GameConfig.playerColor`. This already works with dynamic getters. Also update _glowPaint color in resetVisuals(). The constructor paint will read the current theme at creation time.

2. **Obstacle**: If it uses static Paint objects, add a static `refreshThemeColors()` method that reassigns paint colors from GameConfig. Call this when theme changes. New obstacles created after theme change will naturally use current colors since they're created from GameConfig getters.

3. **GameBackground**: Add a `refreshThemeColors()` method that updates _gridPaint color from GameConfig.gridColor/gridOpacity. Call from PulseGame when theme changes.

4. **BackgroundPulse**: Check if it caches pulseColor. If so, add refresh method.

5. **PulseGame**:
   - On onLoad(), read selectedThemeId from ProgressionRepository and set GameConfig.activeTheme
   - Add `applyTheme(String themeId)` method that:
     a. Sets GameConfig.activeTheme = ColorThemes.getById(themeId)
     b. Persists via ProgressionRepository.instance.setSelectedTheme(themeId)
     c. Calls refresh methods on Player, Obstacle static paints, GameBackground, BackgroundPulse
     d. This is called from the gallery screen (Plan 07-05)

6. **DeathParticles / DodgeSparkle**: These create paint in render lambdas reading GameConfig.playerColor dynamically — already works, no changes needed.

7. **FlashOverlay**: White flash — not themed, no changes.

8. **DangerTint**: Uses fixed dangerTintColor — not themed, no changes.

Test: Set GameConfig.activeTheme to a different theme before the game loads and verify all colors update correctly.
  </action>
