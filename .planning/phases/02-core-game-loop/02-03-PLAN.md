  <files>lib/game/components/player.dart, lib/game/components/obstacle.dart</files>
  <action>
    1. Add hitbox to Player in `onLoad()`:
       - Add `RectangleHitbox()` — will auto-size to component dimensions
       - Player hitbox should be slightly smaller than visual to be forgiving:
         `RectangleHitbox.relative(Vector2(0.8, 0.8), parentSize: size, position: size * 0.1)`
         This gives a hitbox that's 80% of player size, centered — makes near-misses feel fair
       - Player uses default CollisionType.active (it detects collisions)

    2. Add hitbox to Obstacle in `onLoad()`:
       - Add `RectangleHitbox()` — auto-sized to obstacle dimensions
       - Set `collisionType = CollisionType.passive` — obstacles don't need to detect each other
       - Passive is critical for performance: only active-vs-passive and active-vs-active pairs are checked
       - Full-size hitbox for obstacles (no forgiveness on obstacles — they ARE the threat)

    Import `package:flame/collisions.dart` in both files.
    Do NOT add CollisionCallbacks yet — that's Task 2.
  </action>

<task type="auto">
  <name>Task 2: Implement collision callbacks to trigger game over</name>
  <files>lib/game/components/player.dart</files>
  <action>
    1. Add `CollisionCallbacks` mixin to Player class:
       - `class Player extends PositionComponent with HasGameReference<PulseGame>, CollisionCallbacks`

    2. Override `onCollisionStart(Set<Vector2> intersectionPoints, PositionComponent other)`:
       - Check `if (other is Obstacle)` — only react to obstacle collisions
       - Call `game.gameOver()` — triggers state transition, shows GameOver overlay, pauses game
       - This is the ONLY collision handler needed — player hitting obstacle = death, period

    3. Guard against multiple collision calls:
       - Check `if (game.state != GameState.playing) return;` at start of callback
       - Without this guard, multiple obstacles hitting simultaneously could call gameOver() multiple times
       - The guard ensures clean single transition

    Do NOT add death animations or effects — that's Phase 4 (Visual Juice).
    Do NOT add near-miss detection — that's Phase 4/6.
    Keep collision response simple: hit = dead. No health, no shields, no invincibility frames.
  </action>
  <verify>

    Run app — when player overlaps an obstacle, game transitions to GameOver state.
    GameOver overlay appears.
    Game pauses (obstacles stop falling).
  </verify>
  <done>Player collision with obstacle triggers gameOver(), state transitions cleanly, game pauses on death</done>
