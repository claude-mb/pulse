Create a new `lib/game/models/` directory and `obstacle_pattern.dart` with two classes:

**ObstaclePlacement**: Immutable data class defining a single obstacle within a pattern.
- `normalizedX` (double, 0.0-1.0): Position within the play area (0.0 = playerMinX, 1.0 = playerMaxX)
- `yOffset` (double, default 0.0): Vertical offset from spawn line. Negative values = further above screen = arrives later. At speed 280, yOffset of -100 adds ~0.36s delay.
- `widthOverride` (double?, optional): Override default obstacle width

**ObstaclePattern**: Defines a complete pattern.
- `id` (String): Pattern identifier for logging/debugging
- `difficulty` (int, 1-5): Minimum difficulty level to appear
- `placements` (List<ObstaclePlacement>): The obstacle positions in this pattern
- `postDelay` (double, default 0.0): Extra seconds after this pattern before next pattern spawns (gives breathing room after complex patterns)
- A factory constructor or static method `generate` that takes a `Random` and returns a concrete `ObstaclePattern` — this allows patterns with randomized gap positions

Use const constructors where possible. Do NOT use code generation or external packages — plain Dart classes with named parameters.

<task type="auto">
  <name>Task 2: Define 4 core obstacle patterns</name>
  <files>lib/game/config/patterns.dart, lib/game/config/game_config.dart</files>
  <action>
Create `lib/game/config/patterns.dart` with a `Patterns` class (static, private constructor like GameConfig) containing factory methods that produce ObstaclePattern instances. Each factory takes a `Random` for randomized placement.

**Pattern definitions:**

1. **single** (difficulty: 1) — One obstacle at a random x position. This is the current behavior expressed as a pattern. Width varies 50-80px. No postDelay.

2. **doubleGap** (difficulty: 2) — Two obstacles placed to create a gap the player must be in. Pick a random gap center (ensuring gap is within play area). Place one obstacle to the left of the gap and one to the right. Gap width must be >= 80px (player hitbox 32px + generous margin for dodge feel). Obstacles should be wide enough to block their side (70-100px each). postDelay 0.2s.

3. **stagger** (difficulty: 2) — Two obstacles at different x positions with y-offset between them, forcing a dodge sequence. First obstacle at random x. Second obstacle offset by at least 120px (one dodge distance) horizontally and yOffset of -140 (arrives ~0.5s later at speed 280). This creates a "dodge left then dodge right" (or vice versa) rhythm. postDelay 0.3s.

4. **wave** (difficulty: 3) — Three obstacles in a diagonal line across the play area. Pick direction (left-to-right or right-to-left randomly). Space obstacles ~100px apart horizontally with yOffset increments of -100 between each. Player must weave through by timing dodges. postDelay 0.4s.

Add pattern-related constants to GameConfig:
- `minGapWidth`: 80.0 (minimum survivable gap between obstacles in a pattern)
- `patternPostDelayBase`: The postDelay values above

Each pattern's generate method must ensure all obstacle x positions are within playerMinX to playerMaxX bounds, and at least one gap of minGapWidth exists.
