<task type="auto">
  <name>Task 1: Create PatternSequencer with weighted random selection</name>
  <files>lib/game/managers/pattern_sequencer.dart</files>
  <action>
Create `PatternSequencer` class that selects which pattern to spawn next.

**Fields:**
- `_patterns`: List of available pattern factory functions (from Patterns class)
- `_weights`: Map of pattern id to current weight (higher = more likely)
- `_random`: Random instance
- `_history`: List of last 3 pattern ids (for anti-repetition in Plan 03-05, just track for now)
- `_currentDifficulty`: int (1-5), defaults to 1. Controls which patterns are available.

**Methods:**
- `PatternSequencer({required Random random})`: Constructor
- `ObstaclePattern next()`: Select and return the next pattern using weighted random selection. Only consider patterns where `pattern.difficulty <= _currentDifficulty`. Use standard weighted random: sum weights of eligible patterns, pick random value in [0, sum), iterate to find selection.
- `void setDifficulty(int level)`: Update difficulty level (1-5). At difficulty 1, only single pattern. At 2, add doubleGap and stagger. At 3+, add wave.
- `void reset()`: Clear history, reset to difficulty 1.

**Initial weights** (all equal for now — Plan 03-03 will make them dynamic):
- single: 1.0
- doubleGap: 1.0
- stagger: 1.0
- wave: 1.0

The sequencer does NOT spawn anything — it only selects patterns. The spawner handles instantiation.

  <action>
Refactor ObstacleSpawner to spawn patterns instead of single obstacles:

**ObstacleSpawner changes:**
- Add `late PatternSequencer _sequencer` field, initialized in onLoad or constructor
- Replace the single-obstacle spawn logic in `update()` with pattern-based spawning:
  1. When timer fires, call `_sequencer.next()` to get a pattern
  2. For each ObstaclePlacement in the pattern, create an Obstacle at the correct world position:
     - x = playerMinX + normalizedX * (playerMaxX - playerMinX)
     - y = obstacleSpawnY + placement.yOffset
     - width = placement.widthOverride ?? random width between min/max
  3. After spawning a pattern, add `pattern.postDelay` to the timer (delays next pattern)
- Remove the old `_pickSpawnX()` and `_lastSpawnX` anti-clustering logic (patterns handle their own spacing)
- Keep the `reset()` method — also reset the sequencer
- Keep state-gated spawning (only when GameState.playing)

**Obstacle changes:**
- Add optional `speed` parameter to Obstacle constructor (default: GameConfig.obstacleSpeed). Store as instance field. Use in update() instead of reading GameConfig directly. This prepares for Plan 03-03 where speed varies with difficulty.

**PulseGame changes:**
- No changes needed — ObstacleSpawner interface stays the same (it's a Component in the world)

**Do NOT change:** clearObstacles() in PulseGame (still queries world children by type), ScreenHitbox setup, collision detection logic.
