  <action>
Add fairness guarantees to the pattern system:

**Gap validation helper** (in obstacle_pattern.dart or a utility):
Create a static method `validateGap(List<ObstaclePlacement> placements, double minGap, double playAreaWidth)` that:
1. Sorts placements by normalizedX for each yOffset group (obstacles at same y arrive together)
2. For each y-group, checks that at least one gap >= minGap exists between obstacles (or at the edges)
3. Returns true if all y-groups have a survivable path

**Difficulty-aware gap sizing** (in patterns.dart):
Modify pattern factory methods to accept an optional `gapScale` parameter (default 1.0, range 0.7-1.0):
- At difficulty 1-2: gapScale = 1.0 (full 80px+ gaps — generous)
- At difficulty 3: gapScale = 0.9 (72px gaps — tighter)
- At difficulty 4: gapScale = 0.8 (64px gaps — demanding)
- At difficulty 5: gapScale = 0.75 (60px gaps — minimum survivable, player hitbox is 32px)

The minimum gap MUST never go below 55px (32px hitbox + 23px tolerance for dodge animation precision). Add `minSurvivableGap = 55.0` to GameConfig.

**Update ObstacleSpawner** to pass gapScale from DifficultyManager when generating patterns. Add a `gapScale` getter to DifficultyManager based on difficulty level.

Ensure every pattern's generate() method calls validateGap as a debug assertion — if a pattern ever generates an unfair layout, it regenerates (max 5 attempts, then falls back to single pattern).

  <action>
Add a 5th pattern — the most challenging obstacle formation:

**wallWithGap** (difficulty: 4):
- 3-4 obstacles spanning most of the play area width, with exactly one gap
- Gap position is random but always within player-reachable area
- Gap width follows gapScale (80px at scale 1.0, down to 60px at scale 0.75)
- Obstacles fill the rest of the width on both sides of the gap
- No yOffset — all obstacles arrive simultaneously (wall effect)
- postDelay 0.5s (need breathing room after a wall)

**Implementation approach:**
1. Pick random gap center within play area (ensure gap edges don't go out of bounds)
2. Place obstacles to fill the space left and right of the gap
3. Left side: 1-2 obstacles covering from left edge to gap start
4. Right side: 1-2 obstacles covering from gap end to right edge
5. Validate gap width >= minSurvivableGap

**Register in PatternSequencer:**
- Add wallWithGap to the available patterns list
- Weight: 1.0 (same as others — the difficulty gating handles when it appears)
- Only available at difficulty >= 4

This pattern is the "oh no" moment — player sees a wall approaching and must position precisely in the gap. Combined with speed escalation, this creates intense high-difficulty gameplay.
